gui_port_indev.c 不再直接包含具体 touch 头文件，也不直接使用 DEVICE_DT_GET()。它只调用公共 touch API：

gui_port_indev.c
  → rtk_touch_get_data()
  → rtk_touch_get_timeout_ms()
  → input/touch/core/rtk_touch.c
  → input/touch/ports/zephyr/rtk_touch_zephyr.c
  → input/touch/controller/zephyr/（CHSC6417 / CHSC6413 / CST816D / CST820）

03统一 API

提交

int rtk_display_submit(rtk_display_t *disp,
                       const uint8_t *buf,
                       uint32_t len_pixels,
                       uint32_t timeout_ms);

int rtk_display_wait_complete(rtk_display_t *disp,
                              uint32_t timeout_ms);

int rtk_display_commit(rtk_display_t *disp,
                       const uint8_t *buf,
                       uint32_t len_pixels);

int rtk_display_write_region(rtk_display_t *disp,
                             uint16_t x, uint16_t y,
                             uint16_t w, uint16_t h,
                             const uint8_t *buf,
                             uint32_t len_pixels);

submit 语义

类型submit 内部行为返回时
SDI / DBIB 等上一笔完成 → arm → start 当前传输异步进行
RGB arm → switch address → 等 TX_AUTO_DONE + CURR_SAR 地址已切换，可安全画下一帧

len_pixels 是像素数，不是字节数。RGB 必须整帧； SDI 支持 write_region。

submit 后再等待

rtk_display_submit(disp, buf, pixels, timeout);

/* 可选：SDI 等待当前完成；RGB 已是 no-op */
rtk_display_wait_complete(disp, timeout);

状态由 pending 管理。显式 wait 会消费一次 pending， 下一次 submit 不会重复等待。超时则 pending 保留，下一次 submit 可重试。

04中断与等待

所有 controller 共用一个中断：

项目值
IRQDisplay_IRQn（67）
VectorDISPLAY_VECTORn
StatusLCDC_STATUS_TX_AUTO_DONE_INT
MaskLCDC_INT_MASK_TX_AUTO_DONE
ClearLCDC_CLR_TX_AUTO_DONE
关键：LCDC_Init() 会把 mask 位置 1（屏蔽）。 必须用 LCDC_MaskINTConfig(..., DISABLE) 解除 TX_AUTO_DONE 的 mask。用 ENABLE 会继续屏蔽， 表现就是等待永远不返回。 
static void rtk_display_irq_handler(void)
{
    if (LCDC_GetINTStatus(LCDC_STATUS_TX_AUTO_DONE_INT) == SET)
    {
        LCDC_ClearINTPendingBit(LCDC_CLR_TX_AUTO_DONE);
        os_sem_give(display_sync_sem);
    }
}

初始化顺序

rtk_display_init()
  ├─ controller init（LCDC / DBIC / eDPI）
  └─ rtk_display_irq_init()
       ├─ os_sem_create()
       ├─ RamVectorTableUpdate(DISPLAY_VECTORn, ...)
       ├─ LCDC_ClearINTPendingBit()
       ├─ LCDC_MaskINTConfig(..., DISABLE)
       └─ NVIC_Init(Display_IRQn)

IRQ init 必须在 controller init 之后，否则 LCDC_Init() 会覆盖中断配置。

05Buffer 与刷屏

DC_DOUBLE / FULL

HoneyGUI 使用两块 PSRAM full buffer：

dc.type        = DC_DOUBLE;
dc.disp_buf_1  = full_fb_a;
dc.disp_buf_2  = full_fb_b;

每帧画 back buffer，结束时 port_gui_lcd_update_full() 调用 rtk_display_submit()。

DC_RAMLESS / PFB

HoneyGUI 使用两块 section buffer；每节渲染后 GDMA 拷贝到 full buffer， 帧末统一提交。

section buffer
  → GDMA
  → full PSRAM framebuffer
  → rtk_display_submit()
PFB 是渲染策略，不代表底层没有 full framebuffer。当前 QSPI / RGB 的 DC_RAMLESS 都保留 full buffer。

RGB 双缓冲

画 back buffer
  → rtk_display_submit()
      → arm TX_AUTO_DONE
      → LCDC_DMA_Infinite_Buf_Update(new_fb)
      → 等 TX_AUTO_DONE
      → 确认 CURR_SAR 在 new_fb 内
  → return
  → 下一帧写旧 buffer

等待时 GUI 线程 suspend，其它线程可运行。等待不是 CPU 空转，而是 buffer 仍被 DMA 扫描的依赖。要彻底消除该等待需要第三块 full buffer。

08Legacy 清理

旧 SDK 使用 display 冻结副本；device 仓库已移除 8773G legacy。

已移除说明
device/legacy/8773G/lcd/（已移除） ST7265 / ST7701S / ST7789 / ST77916 8080
rtl87x3g-display-lcd-8080.c旧 8080 wrapper
rtl87x3g-display-lcd-rgb.c旧 RGB wrapper
rtl87x3g-display-lcd-spi.c旧 SPI wrapper
rtk_sdi_hal_*旧 default-handle 兼容层
rtk_sdi_bind_panel()不再需要
rtk_sdi_set_default()不再需要

rtk_sdi_get_default() 保留，仅给 auto-detect panel 的 ops->init() 使用。

display 的 legacy Kconfig 仍可能保留 HX8369 / ST7265 / ST7789 / ST77916_8080 等旧符号，这是旧 SDK/其它 SoC 范围，不属于 8773G device 清理。

09Zephyr / FreeRTOS

公共层只使用已有 OS 封装，不直接依赖 Zephyr 或 FreeRTOS API。

os_sem_create()
os_sem_take()
os_sem_give()

RamVectorTableUpdate(DISPLAY_VECTORn, handler)
NVIC_Init(Display_IRQn)

Zephyr 不把 IRQ_CONNECT 放进公共 device 层； FreeRTOS 也不需要额外实现 Display_IRQHandler。 两端都通过 os_sem_* 和 RAM vector table 适配。

Zephyr display API

display_writeSDIRGB
full framertk_display_commit() rtk_display_commit()
regionrtk_display_write_region() -ENOTSUP

Zephyr wrapper 在 POST_KERNEL 只注册设备；真实硬件 init 仍在 gui_server_init() 之后。

11后续工作

  1. 超时恢复：rtk_rgb_confirm_switch() 目前无限等 CURR_SAR，需要加超时。
  2. 有限提交超时：GUI 当前使用 RTK_DISPLAY_WAIT_FOREVER， 可改为有限超时并记录错误。
  3. DBIB 实机：统一使用 TX_AUTO_DONE，需 DBIB 面板确认。
  4. RGB 性能：测量 submit 等待时间；若帧率不足，再评估 triple buffer。
  5. Dcache：当前 port_lcd_dcache_clean() 处于 #if 0，硬件确认后再决定是否恢复。
